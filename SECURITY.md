# Security Policy

## Reporting a Security Vulnerability

The security of Uncle-Factz and its contributors is important to us.

If you discover a security vulnerability, please **do not create a public GitHub issue** with details of the vulnerability.

Instead, contact the project maintainer privately through the contact information available on the repository's GitHub profile.

When reporting a vulnerability, please include:

* A brief description of the issue
* Steps to reproduce it, if possible
* The potential impact
* Any relevant screenshots, logs, or code

Please give the maintainers reasonable time to investigate and address the issue before publicly disclosing the vulnerability.

## What Not to Share

Never publicly share:

* API keys
* Private keys
* Passwords
* Authentication tokens
* Wallet credentials
* `.env` files
* Other sensitive information

If you accidentally expose a secret, revoke or rotate it immediately.

## Scope

This policy applies to security issues affecting the Uncle-Factz source code, backend, frontend, smart contracts, APIs, and related project infrastructure.

Thank you for helping keep Uncle-Factz secure. 🔐
